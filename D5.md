# Adversarial workloads and why they matter

These notes describe the workloads used to exercise the leaderboard's
correctness and update costs. See [D5](docs/derivations/D5_250041008.pdf) for
the AVL split and insertion-rotation proofs.

## Correctness contract

Sort by score descending, then ID ascending. Rank(p) is one plus the number
of strictly higher scores. Select(k) is the unique player at position k.
For players (5,100), (3,90), (8,90), (2,70), ranks in display order are
1,2,2,4; select(3) returns ID 8. Split at 90 places the first three in high.
A successful split/merge consumes its source board IDs.

## Rotation pressure

An ordinary BST can acquire height n under sorted insertion. An AVL must repair
the first ancestor with balance magnitude two. Three distinct scores in each
of the four zig/straight arrangements exercise the two single and two double
rotation forms (score order reverses numeric order in this leaderboard).
Both metadata fields must be refreshed from children after pointer changes.
Balance alone does not imply correct selection: stale subtree size changes
which branch select(k) chooses. Therefore the reused checker recomputes height
and size independently rather than trusting cached fields.

The cascade case uses the recurrence N(h)=1+N(h-1)+N(h-2) to choose a
minimum-node tree at the largest height within the player budget. It inserts
level by level and deletes along the shorter-child path. With 88 players the
current AVL builds height 9 without rotations, then performs eight primitive
rotations on the deletion.

Eight is the upper bound at height 9. Before deletion, a rotating ancestor
of height h had children of heights h-1 and h-2, and the deletion shrank the
shorter child. Consecutive rotating ancestors therefore differ in their
original heights by at least two. The first has height at least three, so
at most four ancestors can rotate, with at most two primitive rotations each.

## Fenwick tie-bucket lower bound

A Fenwick prefix query uses O(log U) count blocks. It does not order the players
inside a tied-score bucket. The present implementation uses a sorted vector.
Insert t players with equal score in decreasing ID order. Before insertion j,
the new ID precedes all j-1 old IDs; vector insertion must shift j-1 entries.
The total shifts are sum(j-1), j=1..t = t(t-1)/2 = Theta(t^2).
The replay also reserves coordinate 91 for a later revision, so the full
compressed domain has U=2. Count updates are still constant time for this
workload, and the population build is quadratic because of the shifts.
AVL insertion remains
O(log j) per player, O(t log t) overall. This is a predicted implementation cost,
not a timing measurement. The small automated tie fixture checks correctness;
larger tie traces are available for the benchmark owner to time separately.

## Split and ordered join

For threshold c, H={p:score(p)>=c}, L={p:score(p)<c}. H and L are disjoint,
their union is the original board, and equality is always assigned to H.
Using c=INT64_MIN yields an empty low side; using INT64_MAX yields an empty
high side only when no player actually has that maximum score.

An AVL ordered join requires every left key before the pivot and every right
key after it. It descends the taller spine until heights are compatible and
repairs the return path. With a supplied separating pivot its target cost is
O(1+|h_left-h_right|). At budget 64, `unequal` starts with board heights 1
and 8. The merge extracts the singleton as pivot, so the ordered join itself
receives trees of heights 0 and 8. The public merge also checks conflicts by
sorting IDs. For overlapping ranges it merges ordered node lists and rebuilds
a balanced tree. With at least four players, `seasons` makes the ranges
overlap by moving one low-division player above the high division.

## Boundary and rejection properties

Scores span int64. Compare fields directly: subtraction can overflow when one
score is INT64_MIN and another INT64_MAX. IDs are uint64 in the shared contract,
and the final backends and application all preserve that width. Full-width
fixtures now check both production backends as well as the oracle.

After a rejected command, later valid rank/size/page queries must still observe
the preceding state. Duplicate-ID ADD, wrong-board access, bad positions and
malformed numbers test different layers. The static regression fixtures additionally cover blank lines, retired board
IDs and error precedence under the selected final INTERFACE.md contract.

## Reproducibility, reduction and scale

A fixed seed, mt19937_64 and explicit modulo decisions produce the same mixed
command stream. Reproducibility is checked by generating twice and comparing
the complete output. A failing trace should be replayed against the merged
sources, reduced, and retained with seed, generator options, compiler and hashes.
Om's existing reducer preserves the same failure signature while removing
commands and converges to 1-minimality under single-command deletion.

Auditing every operation at n live players costs at least Omega(n) per operation,
so doing it for n setup steps costs Omega(n^2). Use a bounded population for long
exhaustive differential traces, and use phase-boundary audits for million-player
tests. The streaming scale generator produces n ADDs, r SETs, two rank queries
and one select query every 1,000 revisions, and a final split and rejoin with
queries. It checks positions 40 through 50 on the full board when n ≥ 50.
It uses constant auxiliary generator memory.
