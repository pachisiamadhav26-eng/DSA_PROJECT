## The size invariant

A player's key is ordered by **decreasing score**, then **increasing player ID**. For a node v, size(v) is the number of players in its subtree, including v. The empty subtree has size 0. A correct stored size satisfies:

    size(v) = 1 + size(v.left) + size(v.right)

## 1. Single rotations

In the left rotation below, A, B, and C are unchanged subtrees. Let a, b, and c be their sizes. The same keys appear in the same in-order sequence: A, x, B, y, C.

           Before: root x                  After: root y
                   x                               y
                  / \                             / \
                 A   y                           x   C
                    / \                         / \
                   B   C                       A   B

After reconnecting the children, refresh **x first**. Its new size is 1 + a + b. Then refresh **y**, whose left child is now x. Its new size is 1 + size(x) + c = 2 + a + b + c. Only x and y changed children, and the subtree still contains exactly 2 + a + b + c players.

A right rotation reverses the picture. Refresh **y first** with size 1 + b + c, then refresh **x** with size 1 + a + size(y) = 2 + a + b + c. In both directions, the demoted node must be refreshed before the promoted node because the promoted node depends on the new child size.

## 2. Double rotations

For a left-right rotation, first rotate left at y, then rotate right at x. The unchanged subtree sizes are a, b, c, and d.

         Before                  After left at y            After right at x
            x                            x                          z
           / \                          / \                        / \
          y   D                        z   D                      y   x
         / \                          / \                        / \ / \
        A   z                        y   C                      A  B C  D
           / \                      / \
          B   C                    A   B

The first rotation leaves correct sizes at y and z and preserves the total size of x's left subtree. After the second rotation, size(y) = 1 + a + b and size(x) = 1 + c + d. Refreshing z after its children gives size(z) = 1 + size(y) + size(x) = 3 + a + b + c + d.

The right-left case is the mirror: rotate right at the right child, then left at the root. Both steps obey the single-rotation rule, so the sizes remain correct.

## Why the invariant holds after updates

An empty tree has size 0 and a new leaf has size 1. In insertion, deletion, or join, work back up from the children. Once their sizes are correct, refreshing their parent gives its exact size. Any rotation at that parent preserves correctness by the proofs on page 1. Applying this reasoning at every changed ancestor restores the invariant throughout the tree.

## 3. Selecting the k-th player

The in-order sequence at a node v is its left subtree, then v, then its right subtree. Let L = size(v.left). The loop invariant is that the desired player is the k-th entry in the current subtree, with 1 <= k <= size(current).

- **k <= L:** The desired entry is on the left. Descend left and keep k unchanged.
- **k = L + 1:** The desired entry is the current node. Return it.
- **k > L + 1:** The left subtree and the current node account for L + 1 earlier entries. Descend right and replace k by k - L - 1.

These three cases partition the current subtree's positions. On a descent, the new k remains in range for the chosen child and refers to the same player. Each descent reduces the height. The algorithm therefore reaches and returns the desired player. An empty tree has no valid position, and k = 0 or k > size(root) is rejected before the search.

**Worked example.** Suppose the displayed player IDs are 1, 2, 3, and 4, with scores 100, 90, 90, and 70. If the root is player 2, its left subtree has one player. For select(3), skip L + 1 = 2 entries and search for position 1 in the right subtree. This returns player 3, who shares competition rank 2 with player 2.

## 4. Running time

At each node, reading the stored left size and choosing a branch take O(1) time. The search follows at most one root-to-leaf path, so it takes O(h) time and O(1) extra space, where h is the tree's height.

Let N(h) be the minimum number of nodes in an AVL tree of height h. With an empty tree of height 0, N(0) = 0 and N(1) = 1. For h >= 2, one child must have height h - 1 and the other must have height at least h - 2. The minimum is attained by attaching the smallest trees of heights h - 1 and h - 2 to a new root. Therefore:

    N(h) = 1 + N(h - 1) + N(h - 2)
    N(h) + 1 >= 2 * (N(h - 2) + 1)

The second inequality follows because N(h - 1) >= N(h - 2). Iterating it shows that the minimum node count grows exponentially with height, so an AVL tree with n nodes has h = O(log(n + 1)). Thus selection takes **O(log n) time** for n >= 2 and constant time on a singleton.

## Connection to the implementation

The AVL functions `rotateLeft` and `rotateRight` call `refresh` in the order shown on page 1. The AVL `select` method uses the three cases above. The independent oracle reads entry k - 1 in its sorted vector. The test harness compares exact player IDs and scores and calls `audit_avl`, which recomputes heights and sizes from the child links.
