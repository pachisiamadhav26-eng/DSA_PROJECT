# D6 Predicted operation costs

Module owner: Sumit Dobal

Use n for live players, U for compressed score coordinates and t for a
tie bucket size. Timing the backends uses precomputed query inputs and
excludes preprocessing, parsing, hash lookups and output.

## Rank and selection

AVL rank counting and select each follow one root-to-leaf path with
constant work per node. With h the actual height, use T_A = a+b*h as a
worst-path model, with h=O(log(n+1)). Actual paths can end earlier.
Fenwick rank uses a binary search of U scores and a prefix query. For
prefix endpoint i its second phase takes popcount(i) iterations. Model
it as T_B = c+d*ceil(log2(U+1))+e*popcount(i), which is O(log(U+1)).

Fenwick select tries floor(log2(U))+1 powers and indexes one sorted
bucket at the end. The cost model is f+g*(floor(log2(U))+1) for U>=1.
Increasing t at fixed n shrinks U. Holding U fixed while increasing n
mainly increases bucket sizes. In a tie, the returned position depends
on the ID offset while competition rank stays the same.

## Season operations

AVL score split follows a search path and joins partial results. Its
height increments telescope, so the model is a+b*h, with a separate
counter for the join visits. Ordered join with supplied pivot takes
c+d*|hL-hR|. The separated rejoin measured through merge_from also
searches for a boundary and removes the pivot, adding O(log(n+1)).
Overlapping AVL merge traverses both trees, merges their ordered keys
and builds a balanced tree in O(nL+nR).

Fenwick split moves whole buckets and rebuilds two count arrays, so
use a+b*U for a nonempty source. Rejoin over the same coordinates
uses a+b*U+c*M, where M counts entries copied in buckets occupied on
both sides. M=0 for separated score halves. Different coordinate
domains also need an ordered union and may copy all entries. Empty
boards can take faster paths in either implementation.

## Updates and counters

AVL updates traverse height h and do constant work per visited node.
Fenwick updates touch O(log U) count blocks, plus search in the affected
bucket and shift a suffix of that bucket. Inserting a full group of t
ID values in decreasing order shifts t*(t-1)/2 existing entries.

Record five timed trials for each configuration, reporting mean and
min/max. Compare measured slopes with the models and use rotation,
bucket shift and join visit counters to explain the work performed.
Memory layout could affect timings. Attribute effects to cache behavior
only when hardware profiles support the claim.
