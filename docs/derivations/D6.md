## 1. Definitions and measured scope

n is active players; U is prepared score coordinates, including unused scores; N = n1 + n2 for two boards; h1, h2 are AVL heights. Order is decreasing score then increasing ID. Competition rank is 1 plus strictly-higher-score count; select(k) uses one-based display positions. Coefficients below are symbolic implementation/machine costs, not calibrated nanosecond values. Counts are operation-specific: v = visited AVL nodes, c = coordinate comparisons, f = inspected Fenwick count entries.

Code versions: Architect a4dc438, AVL 03f3f57, Fenwick 2d758ef and Oracle f3f8c29. The original Fenwick model used 0d5ad68; its measured fenwick.cpp is identical. The newer Oracle affects untimed checks. Full commits and hashes are in the formal run's metadata.json.

## 2. AVL rank and select

The minimum-node AVL recurrence is M(0)=0, M(1)=1 and M(h)=1+M(h-1)+M(h-2). Its exponential growth gives h=O(log(n+1)). For rank, when a node's score exceeds the query score, add size(left)+1 and go right; otherwise go left. The skipped players are all strictly higher. For select, compare k with size(left)+1; go left, return the node, or subtract that position and go right. Both follow one downward path with constant work per visited node, so both cost O(log(n+1)).

Models: `T_rank_A = a0 + a1*v`; `T_select_A = b0 + b1*v`. The zero-index coefficients represent fixed overhead; a1 and b1 model per-visit work. They need not be equal.

Code: `avl.cpp`: `AvlBoard::count_strictly_higher`, `AvlBoard::select`. Measurement: `bench/runner.cpp::queries` adds one to the higher-score count and times rank/select separately.

## 3. Fenwick rank and select

Rank binary-searches descending coordinates, then takes the prefix count before the score bucket. Binary search is O(log(U+1)); each prefix step clears the lowest set bit, giving O(log(U+1)) count steps. Select tests descending powers of two to locate the first prefix reaching k, then directly indexes its sorted ID bucket in O(1). Its initial jump setup and search are logarithmic. Both queries cost O(log(U+1)), independently of bucket length once IDs are ordered.

Models: `T_rank_B = c0 + c1*c + c2*f`; `T_select_B = d0 + d1*f`. Coefficients scale comparison/count-step work and overhead. Fixed U bounds the algorithmic search work, but does not guarantee identical elapsed times as n changes.

Code: `src/structB/fenwick.cpp`: `FenwickBoard::scoreIndex`, `prefix`, `count_strictly_higher`, `select`. Measurement: `bench/runner.cpp::queries`.

## 4. Revisions surrounding queries

AVL erase plus insert costs O(log(n+1)). Fenwick must also shift sorted IDs: removing/inserting can cost the old/new bucket lengths, giving O(log(U+1)+t_old+t_new). Count updates alone omit this work. Code: both backends' `erase`/`insert`; Fenwick's `add`. Revisions and player-score lookup stay outside core query timers.

## 5. Split against rebuilding

AVL split follows a search path and joins saved branches into two outputs. Using D1 and D5, charge each return step O(1+delta), with delta the output height gain. Output heights grow monotonically, each ending at most at original height H. The two telescoping gain sums total at most 2H, with at most H return steps. Thus split is O(H)=O(log(n+1)), rather than charging a full-height join independently at every level.

Fenwick copies prepared coordinate arrays, moves bucket-vector storage, and rebuilds counts. It scans U coordinates a bounded number of times: O(U+1). Moving a bucket transfers its storage, not each ID. Output-array allocation remains inside the public split cost. Threshold ties enter the high division.

Models: `T_split_A = e0 + e1*log2(n+1)`; `T_split_B = f0 + f1*U`. The AVL term proxies path/join work; the Fenwick term scales coordinate work. Constants include allocation and implementation overhead.

Code: `avl.cpp`: `splitScore`, `joinNodes`, `AvlBoard::split_by_score`. `src/structB/fenwick.cpp`: `FenwickBoard::split_by_score`, `rebuild`. Measurement: `bench/runner.cpp::seasons`.

## 6. Ordered join, public rejoin and general merge

Ordered AVL join assumes valid trees, distinct IDs and a supplied pivot separating the ordered ranges. If heights differ by at most one, attach directly. Otherwise descend the taller spine until compatible, then rebalance and refresh sizes/heights while returning. Each level does constant work, and height drops by at least one per descent, giving O(abs(h1-h2)+1).

Model: `T_join_A = g0 + g1*(abs(h1-h2)+1)`. Allocation and join are timed; pivot selection and boundary scans are excluded. Code: `avl.cpp::joinNodes`, `avl_join_ordered`. Measurement: `bench/runner.cpp::ordered_join` records actual heights and join visits.

Public AVL rejoin of separated divisions checks boundary nodes, extracts a pivot and joins; the total is O(log(N+1)). Code: `avl.cpp::AvlBoard::merge_from`, `first`, `last`, `takeLast`, `joinNodes`. Overlapping ranges instead collect sorted node lists, merge them and rebuild in O(N), assuming globally unique IDs. That path is not the season rejoin comparison.

Fenwick public merge collects N IDs and sorts them for duplicate detection: O(N log(N+1)). Coordinate combination, bucket-ID merging and count rebuilding add O(U1+U2+N). Total: O(U1+U2+N log(N+1)), including validation even for separated divisions.

Model: `T_merge_B = j0 + j1*(U1+U2) + j2*N + j3*N*log2(N+1)`. Terms model overhead, coordinate work, linear ID work and sorting. Code: `src/structB/fenwick.cpp::FenwickBoard::merge_from`, `hasDuplicateIds`, `rebuild`. Public rejoin measurement: `bench/runner.cpp::seasons` calls `merge_from`.

## 7. Testable predictions and limits

Test n=10^3, 10^4, 10^5, 10^6 with U=n and U=min(n,1000). Each query repetition mixes 10^6 real revisions with 10^6 rank and 10^6 select queries in blocks of up to 256. Same seeds and fresh state give identical workloads. Five repetitions report mean, sample standard deviation and min/max. Setup/checks stay outside query timers; loops/checksums remain inside. Public split/rejoin includes its own allocation/validation. Trace calls include per-call timer overhead.

Predict bounded Fenwick query/split work at fixed U, slow AVL path growth, and height-gap-dependent join work. Public Fenwick merge still grows with N at fixed U. Query visits are not instrumented; owner counters expose rotations, join visits and ID shifts. Cache claims require separate profiler evidence; samples are not exact miss totals. Timing gaps belong in REPORT.md, not retrofitted pre-measurement predictions.
