## Exact assigned statement

> D2 (Structure B owner): The binary-lifting descent returns the smallest index whose prefix count is at least k, in O(log U). Prove it.

## Where the result is used

File: `src/structB/fenwick.cpp`.

Function: `leaderboard::FenwickBoard::select(Position k) const`.

`select` uses this result to locate a score bucket, then indexes the sorted IDs in that bucket to return the exact player. `FenwickBoard::range` calls `select` for each requested position. The Fenwick count array is one-based, while `scores` and `ids` use zero-based vectors.

## Definitions and assumptions

Let U be the number of distinct prepared scores, with c1 > ... > cU.
Bucket i has count a[i] and an
increasing list of its player IDs. Let P(i) = a[1] + ... + a[i], with P(0)=0.
For valid position k, we need the first coordinate i with P(i) >= k. The ID
to return is at one-based offset k - P(i-1) within bucket i.

Every a[i] is nonnegative, so P is nondecreasing. Prepared coordinates may have empty buckets. Write K for the original requested position and k for the residual changed by the implementation. An empty board has no valid query. The implementation rejects k=0 and k>total before starting the descent.

## Search used in the implementation

```cpp
ll n = scores.size();
ll d = 1;
while (d <= n / 2) d *= 2;

ll x = 0;
for (; d > 0; d /= 2) {
    ll next = x + d;
    if (next <= n && bit[next] < (ll)k) {
        k -= bit[next];
        x = next;
    }
}
return {ids[x][k - 1], scores[x]};
```

## Why the tree provides the candidate count

Fenwick cell j stores a[j-lowbit(j)+1] + ... + a[j]. The search keeps a
prefix endpoint x and tries adding powers of two d from largest to smallest.
At the start of the step for d, x is a multiple of 2d. Thus if j = x+d is
in bounds, lowbit(j)=d and bit[j] equals P(j)-P(x).

## Why the greedy decision is correct

Let q be the greatest index with P(q) < K, where K is the original request.
Because P(0)=0<K<=P(U), q exists and lies in 0..U-1.
Nonnegative bucket counts make P monotone. Start with x=0 and remaining=K.
At a step for d, maintain x <= q < x+2d and remaining=K-P(x). The starting
largest power of two makes the bound true since q < U. If x+d <= U and
bit[x+d] < remaining, then P(x+d) < K, so x+d <= q. Move x to x+d and
subtract the block count from remaining. Otherwise x+d is beyond q, so
keep x and remaining. Either way the next bound is x <= q < x+d. The
endpoint is a multiple of d, establishing alignment for the next step.

If x+d is out of bounds, then q<U<x+d, so keeping x also preserves the smaller bound. If it is in bounds but the strict comparison fails, P(x+d)>=K, so q<x+d. These cover both reasons for keeping the current endpoint.

After d=1, the bound gives x=q exactly. Then bucket x+1 is the first with
P(x+1) >= K. The remaining offset is positive and at most that bucket's
count, so indexing its sorted IDs chooses the exact player. Empty buckets
can be skipped because the comparison is strict. Using <= would skip a
prefix whose count already reaches the requested position.

## Cost and distinction from rank

For U>=2, finding the initial power of two and processing its bits each take O(log U) time. For U=1, selection takes O(1). Uniformly, selection costs O(1+log U) for nonempty coordinate sets. The final ID lookup adds O(1), and the descent uses O(1) auxiliary space. Compression and structural auditing are outside this selection bound.

A player rank is 1+P(i-1), so players in bucket i share a competition rank while selection assigns distinct positions. Count updates take O(log U); shifting IDs within a tie can add O(t) time for a bucket of t players.

## Worked example with seven prepared coordinates

| One-based bucket i | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Score | 110 | 100 | 90 | 80 | 75 | 70 | 60 |
| Frequency a[i] | 2 | 0 | 1 | 0 | 0 | 3 | 1 |
| Prefix P(i) | 2 | 2 | 3 | 3 | 3 | 6 | 7 |
| Fenwick bit[i] | 2 | 2 | 1 | 3 | 0 | 3 | 1 |

For K=5, begin with x=0, k=5 and d=4.

| Jump d | Candidate x+d | Block count | Decision | New x | Remaining k |
| --- | --- | --- | --- | --- | --- |
| 4 | 4 | 3 | Skip because 3<5 | 4 | 2 |
| 2 | 6 | 3 | Keep x because 3>=2 | 4 | 2 |
| 1 | 5 | 0 | Skip because 0<2 | 5 | 2 |

The answer is bucket 6 because P(5)=3<5<=6=P(6). If its sorted IDs are [4,8,11], offset 2 returns ID 8 at score 70. This example includes a non-power-of-two coordinate count and empty buckets. For K=3, using <= instead of < at the first step would incorrectly skip the prefix ending at bucket 4, even though bucket 3 is the first bucket reaching 3.
