# D3 - Competition rank is the same in both structures

Author: Madhav Pachisia (Architect)

## Statement

For any active player p with score s, competition rank(p) is one plus the number of active players whose scores are strictly greater than s. The AVL and Fenwick implementations return exactly this value after every valid update, split, and merge.

## Definitions

Let P be the set of active players on one board. Define H(p) = {q in P : score(q) > score(p)}. Players are displayed by decreasing score, with increasing player ID breaking a score tie. A displayed position is unique, but competition rank is shared by all players with the same score.

## Why the rank formula is correct

Every player in H(p) must appear before p's entire equal-score group. No player with score equal to or below score(p) belongs to H(p). Therefore the first position occupied by the equal-score group is |H(p)| + 1. Competition ranking assigns that first position to every member of the group. Hence rank(p) = 1 + |H(p)|. The player-ID tie rule changes positions inside the group but does not change its competition rank.

## AVL computation

The AVL tree uses the total order (higher score first, then smaller ID) and stores each subtree's size. To count scores strictly higher than s, start at the root with count = 0. At a node x with score(x) > s, every node in x's left subtree also has score greater than s. Add size(left(x)) + 1 and continue into the right subtree. At a node with score(x) <= s, x and its entire right subtree cannot have a score greater than s; continue into the left subtree without adding anything.

At each step, the discarded subtree is either counted in full or proved to contain no qualifying player. The counted subtrees and nodes are disjoint. When the search ends, every player with score greater than s has been counted exactly once and no other player has been counted. Correct subtree sizes make this count exact, including after rotations. AVL height is O(log n), so the count and rank take O(log n) time.

## Fenwick computation

Let the distinct compressed scores be c1 > c2 > ... > cU. Coordinate j stores the number of active players whose score is cj. If p has score cj, the scores strictly greater than score(p) are exactly c1 through c(j-1). Their number of players is the prefix count sum(j-1). The Fenwick prefix query returns this sum exactly because its visited blocks are disjoint and cover coordinates 1 through j-1. Therefore rank(p) = 1 + sum(j-1). The query takes O(log U) time. Counts at coordinate j, including all players tied with p, are excluded.

## Agreement after operations

Both calculations count the same set H(p), so they return the same rank. A score revision removes the player's old (score, ID) key or count and adds the new one. Insertions and deletions change the corresponding key or count in both structures. A score-threshold split partitions P into disjoint high and low boards; a successful merge restores the union. As long as each structure preserves its invariants, the same argument applies independently to every resulting board.

## Example

Scores 100, 90, 90, 70 give H sizes 0, 1, 1, 3, and hence ranks 1, 2, 2, 4. The two players at score 90 occupy different displayed positions but have the same competition rank.
